# 게임 설계 (v0)

최종 갱신: 2026-10-06. 그래픽은 후순위라 규칙·확률 모델·구조만 정함.

## 0. 한 줄 요약

실제 KBO 2010~2026 시즌 카드로 팀을 꾸려, 투구마다 "어디로 던질까 / 어디를 노릴까"를 동시에 고르는 수 싸움 야구 게임임.
카드는 그 시즌 기록을 재현하고, 노림수를 잘 읽는 사람이 카드 이상의 결과를 냄.

## 1. 범위

- 비상업, 2인용 (나 + 친구 1명). 1단계 1P vs CPU, 2단계 1P vs 2P 온라인.
- 팀 이름·로고·유니폼은 가상 (`data/franchises.json`의 `display_name`). 선수 실명은 개인용으로만 쓰고 repo는 private 유지.

## 2. 게임 모드

시작 화면: 팀 선택 → 모드 선택 → (선택) 1인칭 ON/OFF → 상대 선택(CPU / 친구)

| 모드 | 로스터 구성 | 비고 |
|---|---|---|
| 연도별 | 그 프랜차이즈의 특정 시즌 실제 로스터 (`rosters.json`) | 2014 히어로즈 vs 2017 타이거즈 같은 시즌 맞대결 |
| 연도 짬뽕 | 그 프랜차이즈 2010~2026 카드 중에서 골라 구성 | 같은 선수는 한 장만 (예: 양현종 2017과 2019 동시 불가) |
| (제안) 드래프트 | 전 구단 카드 풀에서 둘이 번갈아 지명 | 친구와 1:1 할 때 재미 포인트. OVR 합 상한(샐러리캡) 옵션 |

로스터 인원은 설정값 (기본 제안: 타자 13 + 투수 13).
능력치가 시즌 내 상대평가라 2014(타고투저) 타자와 2019(공인구 변경) 투수를 섞어도 공정함.

### 1인칭 토글

- ON이면 로스터에서 카드 1장을 골라 그 카드의 이름을 내 이름으로 바꿈. 능력치는 그 카드 그대로.
  "내가 그 시즌 그 팀에 들어갔다면" 가정.
- 확장 (나중): ① 능력치 직접 배분형 커스텀 선수, ② 내 선수만 조작하고 나머지는 CPU가 하는 커리어 모드.
- 온라인 대전에서는 두 사람 다 각자 1인칭을 켤 수 있음.

## 3. 카드

- 카드 = 선수 × 시즌. 타자 카드와 투수 카드는 별개 (투타겸업은 두 장).
- `ratings` (1~99): 화면 표시·카드 등급용. 시즌 리그 평균 = 50.
- `rates`: 엔진이 확률 계산에 쓰는 시대 중립 비율 (삼진율, 볼넷율, 홈런율, BABIP 등).
- 표본 작은 시즌은 `small_sample` 표시, 진행 중 시즌은 `partial_season` 표시.
- 산식은 `docs/DATA_SPEC.md` 5장.

타자 능력치: 정확도, 컨택, 파워, 선구안, 타구질, 주루, 도루능력, 수비(데이터 보강 후) + OVR
투수 능력치: 구위, 제구, 무브먼트, 피안타억제, 체력 + OVR

## 4. 타석 엔진 (핵심)

### 4.1 한 구의 흐름

1. 투수 측이 고름: 구종 + 목표 칸
2. 타자 측이 동시에 고름: 노림 칸(또는 노림 없음) + 노림 구종(선택) + 대응 방식
3. 공개 → 실제 탄착 계산 → 스윙 판정 → 결과 → 볼카운트 진행

동시에 비공개로 고르는 구조라 온라인 대전에서 반응속도·지연 문제가 없음.

### 4.2 스트라이크존

- 5×5 격자: 가운데 3×3 = 스트라이크존 (1~9번), 바깥 테두리 16칸 = 볼.
- 가운데(5번)는 실투 칸: 안타·장타 확률 큼. 모서리는 투수에게 유리.

### 4.3 제구 → 실제 탄착

- 실제 위치 = 목표 칸 중심 + 정규분포 오차. 오차 크기 σ = σ0 × f(제구) × 피로 보정.
- 제구 낮은 투수는 모서리를 노려도 가운데로 몰리거나 볼이 됨 → 카드의 볼넷율이 자연스럽게 재현되도록 보정.

### 4.4 타자의 선택

- 노림 칸: 1칸 지정 / 한 줄(높은 공·낮은 공) 지정 / 노림 없음.
- 대응 방식: ① 노린 공만 친다 ② 스트라이크면 친다 ③ 기다린다.
- 선구안: 볼 칸으로 온 공에 휘두르기 전에 자동으로 참을 확률. 경계 칸의 스트라이크/볼 판단 정확도.

### 4.5 확률 결합

- 타자 비율과 투수 비율은 odds ratio 방식으로 합침:
  odds(결과) = odds(타자) × odds(투수) / odds(리그). (Bill James log5의 일반형)
- 결과 트리: 스윙 → 헛스윙 / 파울 / 인플레이 → 인플레이면 아웃 / 1루타 / 2루타 / 3루타 / 홈런.
  - 헛스윙: 컨택 vs 구위
  - 정타·장타: 파워 vs 무브먼트
  - 인플레이 안타: 타구질 vs 피안타억제 (+ 수비)
  - 2루타·3루타 비율: 카드의 `double_share`, `triple_share` + 주루

### 4.6 노림수 보정 (공정성 원칙)

- 칸과 구종을 다 맞춤 → 컨택·정타 확률 크게 상승. 같은 줄만 맞춤 → 소폭 상승. 빗나감 → 하락.
- 보정값은 "아무렇게나 고르는 평균적인 사람"의 기대 보정이 1이 되도록 맞춤.
  → CPU 대 CPU로 돌리면 카드 기록이 재현되고, 상대 패턴을 잘 읽는 사람만 카드 이상의 결과를 냄.
- 확인 방법 (캘리브레이션 테스트): 2014 서건창 카드 vs 리그 평균 투수를 수만 타석 돌려 타율·삼진율·볼넷율이 실제 기록 근처인지 자동 검사.

### 4.7 피로·주루

- 체력: 투구수 한도와 피로 곡선. 피로하면 제구 오차↑, 구위↓.
- 주루: 안타 때 추가 진루, 병살 회피, 도루 시도·성공 (도루능력 없으면 주루로 대체).
- 수비: v1은 팀 평균 고정, 데이터 보강 후 포지션별 반영.

## 5. CPU

- 투수 CPU: 볼카운트별 칸·구종 분포 (유리할 때 바깥/유인구, 불리할 때 존 안) + 무작위.
- 타자 CPU: 볼카운트별 노림 분포 + 무작위. 난이도 = 상대 패턴 학습 정도.

## 6. 기술 구조 (제안)

| 영역 | 선택 | 이유 |
|---|---|---|
| 데이터 | Python (`pipeline/`) | 이미 구축. 수집·정규화·능력치 계산 |
| 게임 엔진 | TypeScript, 순수 함수 + 시드 고정 난수 | 브라우저·서버 공용. 같은 시드면 같은 결과 → 온라인 대전 동기화·리플레이 쉬움 |
| 화면 | 웹 브라우저 (v1 텍스트+존 그리드 UI, 그래픽은 나중) | 설치 없이 친구 PC에서 바로 접속 |
| 1:1 대전 | 맥미니에 작은 WebSocket 서버 + Tailscale 등으로 친구 접속 | 매 구 두 사람 선택만 주고받으면 됨. 서버가 난수 굴려서 치팅 방지 |

## 8. 열린 결정사항

1. 투수 100경기 기준에 이닝 보조 기준 추가 여부 (`docs/DATA_SPEC.md` 1장 표).
2. 로스터 인원, 드래프트 모드 포함 여부.
3. 기술 구조(6장) 확정 — 특히 웹 + TypeScript로 갈지.
